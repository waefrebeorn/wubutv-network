## The method (user law 2026-11-10 ~02:06 EST, corrected ~02:13 EST)
1. LAST-FRAME → FIRST-FRAME CHAINING where the scene continues: take
   N+1 is generated with take N's last frame as its first image
   reference (two-image call: image 1 = previous take's last frame,
   image 2 = the scene's own end reference).
2. NEW FIRST FRAMES ARE ALLOWED where the cut turns (new angle, new
   setting, new scene). A fresh first frame must still line up with the
   outgoing frame's WORLD (same lighting, framing family, subject
   position) so the joint doesn't jump. A new start that breaks the
   world is a continuity fail, same as a broken chain.
3. AUTOGENERATED per-project IMAGE-REFERENCE STACK: one start/end
   reference pair per scene, built from this project's own material
   (style lock, KEEP-take states, anchor stills) — never one anchor
   still reused across scenes. Stack lives in work/stills/stack/ +
   REFERENCE_STACK.md, written before volley 1.
4. Prompts timed from the measured music (beat grid, onsets, word
   times). Each prompt carries motion beats keyed to the song's own
   events — never a generic "then it moves."
5. A FULL 10 SECONDS of prompt per take: motion planned 0–3s, 3–7s,
   7–10s, keyed to the song. A prompt that only describes an opening
   image is not a vehicle.
6. Assembly cuts only on in-motion frames; anchor-still heads trimmed.
   Stop-start flow = QC fail. Joint QC: last frame of take N vs first
   frame of take N+1 (frame-diff + eye read: framing, lighting,
   subject position).

## Reference-stack design (THIS project)
Sources, in strength order: (a) the CHARACTER_LOCK style lock (flat bold
2D cartoon, teal tiles / bone-white porcelain / cobalt water / cadmium
duck / vermilion towel, warm lamp gold); (b) the v1 KEEP takes' END
STATES (what each scene's water actually looked like when it landed —
S03's apex crown, S04's rings, S14's rain); (c) the two anchor stills
as world-lock only, never as take openers.
- START refs: S01 = generated "drop falling into still water" (the cold
  open's first frame — the moment BEFORE the splash, which v1 never
  showed). S02 = generated wide-room reveal (FRESH first frame, see
  J01). S03–S06 = CHAIN frames: the previous NEW take's last frame,
  extracted with ffmpeg (`-sseof -0.042`, one frame, 1248x704), never a
  generated still, never a v1 frame.
- END refs: one generated still per scene (S01–S06) showing the exact
  water state the take must land on (crown apex / wide rings / reverse
  splash / gold wash). The end ref is the take's DESTINATION, not its
  opener — per the measured two-image shape (start-anchor → ~0.5s morph
  → invented middle → ~9s in the second image's world), the take spends
  most of its life arriving at its end ref.
- Every stack image is read back (eye + ffprobe 1248x704) before use.
  A drifted ref is re-generated, never used as-is (ref poisoning).

## Chaining protocol
- Extract: `ffmpeg -sseof -0.042 -i <take>.mp4 -frames:v 1
  work/stills/stack/chain_s<NN>_last.png` — one invocation per frame
  (multi-input extraction returns frame 0 for every output — proven
  2026-11-09). Verify the extracted frame differs from the take's
  frame 0 (md5) and shows the take's end state.
- Call shape (two images, ordered entries): [1] TEXT framing + style
  lock + "Wide 16:9 video, exactly 10 seconds" + "the picture is
  already moving at frame 0" + first-image instruction; [2] IMAGE
  chain frame / fresh start ref; [3] TEXT transition naming image 2
  ("This shot continues from the first image and ends at the second
  image") + full-10s motion plan keyed to song beats/words + forbiddens;
  [4] IMAGE end ref; [5] TEXT arrival/end-state.
- Duration: request exactly 10 seconds on every call (v1: 10s requests
  always returned 10.000s; 5s requests returned 5s/6s/10s
  unpredictably). Assembly trims to the slot.
- Never chain from a rejected take. A chain break restarts from the
  last good take's last frame.
- Sequential firing only: S03 needs S02's last frame, S04 needs S03's,
  S05 needs S04's, S06 needs S05's. S01 and S02 are independent of
  each other (S02 is a fresh start) and may fire in any order, but the
  volley still proceeds S01 → S02 → S03 → S04 → S05 → S06 in song order.

## Joint-continuity QC (per joint, before the joint ships)
- Extract take N last frame + take N+1 first frame (one ffmpeg call
  each, distinct md5s verified). Pixel MAE between the two frames +
  eye read: framing, lighting, subject position (bowl, duck, lamp,
  towel). A joint that jumps = FAIL, reroll the downstream take on the
  JOINT axis (one variable: the chain frame or the start ref).
- Per take: full-10s motion audit (mean abs-diff per 0.5s window on
  160x90 gray frames; FAIL = any near-still run ≥12f); G1 identity
  (bowl bone-white, duck yellow/orange beak, teal tiles, lamp, towel);
  G2 zero in-clip text; motion already happening at the first usable
  frame (f0→f2 diff above the scene baseline — no anchor-still head).
- Ledger: work/TAKE_LEDGER_REBUILD.md (one row per take: file, md5,
  duration, joint device, verdict, QC notes). Progress:
  MV11_REBUILD_PROGRESS.md (incremental, short).

## What the proof must prove (and what would fail it)
- PROVES: chained takes open in motion (no anchor-still head), joints
  line up frame-to-frame, and the six takes read as ONE continuous
  shot sequence instead of six separate images.
- FAILS: any take with an anchor-still head ≥12f; any joint that jumps
  (MAE/eye); any take whose first usable frame is still; the morph at
  0.5–1.0s eating the opening song event.
- Open question the proof answers: does the two-image morph (measured:
  start-anchor → ~0.5s morph → invented middle → ~9s in end-ref world)
  preserve the chain, or does it wash the chain frame out? If it washes
  it out, the fallback is single-image chain calls (first-frame lock
  only) for S07–S23.

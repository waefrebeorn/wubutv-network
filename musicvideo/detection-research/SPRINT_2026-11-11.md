## 2. TSM (F-17) per-shot on MV-8 v3 vs rejected v2

Implementation: `detection-research/tsm.py` (numpy + one FFmpeg decode per
master at native 24fps, 160x90 gray; 12fps series = every other frame).
Per-segment results in `tsm_v2.json` / `tsm_v3.json`. Whole-master:

| metric | v2 (rejected) | v3 (accepted) | discriminates? |
|---|---|---|---|
| M1 activity (median diff) | 0.0697 | 0.1079 | YES — v3 55% more active |
| M2 freeze ratio (τf=0.002) | 0.00401 (9/2246) | 0.00712 (16/2246) | NO — wrong direction |
| M2 longest freeze run | 0.17s | 0.33s | NO — wrong direction |
| M3 flicker index (x1000) | 9.17 | 12.52 | no (v3 higher) |
| M4 jitter ratio | 0.3327 | 0.2379 | YES — v2 40% less smooth |
| **M6 duplicate ratio (τd=0.0005)** | **0.19702 (885/4492)** | **0.04942 (222/4492)** | **YES — v2 4.0x higher** |
| M6 longest dup run | 0.12s | 0.08s | weak |
| M5 boundaries found | 36 | 17 | confounded (see below) |

Per-segment M6 (native-rate duplicate share): v2 exceeds v3 in 11/17
segments. Worst v2: O-B 0.409, I-B 0.296, H2-C 0.255, V-0 0.255, I-A
0.214, FH-A 0.212. Worst v3: O-A 0.223 (the accepted master's slow
return-flight drift — longest dup run only 0.04s), H2-B 0.108, H2-C
0.087. Per-segment M1: v3 higher in 15/17. Per-segment M2 max: v3 D-A
0.0533 (longest 0.33s) vs v2 H1-A 0.0208 — again the wrong direction.

Corroboration from the files themselves: same CRF 18, same duration —
v2 is 125.1 MB vs v3 193.6 MB. Flatter, less-detailed motion compresses
smaller.

**Answer to the sprint question: YES, TSM discriminates — via M6, not
M2.** The halted-moment signal in v2 is a high SHARE of near-duplicate
frames (slow/static takes throughout the master), not discrete freezes,
which is exactly why duration-thresholded freezedetect saw nothing in
either master. M1 and M4 support the same reading (v2 = less motion,
less smooth). The paper's headline metric M2 fails on this material.

**Gate proposal (needs one more master pair to calibrate before it is a
gate):** whole-master M6 > 0.10 = flag for eye review (v2 0.197 vs v3
0.049 separates cleanly). Per-segment M6 alone is NOT a gate — v3's
O-A at 0.223 would false-flag; pair it with longest-dup-run, which
stays ≤0.12s in both masters.

**M5 caveat:** as implemented it over-fires — v2's 36 hits include a
6-hit cluster in H1-B (26.33–31.00s) and a triple-fire at
81.08/81.25/81.67. It needs non-max suppression before its count means
anything (recall on planned cuts: v2 13/16, v3 7/16, precision poor).
M4's threshold (3x median |Δd|) is OUR implementation choice, not the
paper's — the preprint leaves M4 relative. The temporal-signature reuse
cross-check (v3 vs its takes) was NOT run — still owed.

## The single most valuable next improvement

**Make M6 the halted-moment gate, and run it on every volley take before
it enters a cut — not on masters after the fact.** The sprint's one
decisive finding is that the rejected master is measurable as "4x more
near-duplicate frames" while every freeze-based check reads zero on
both. A per-take M6 (native-rate duplicate ratio, τd=0.0005, one FFmpeg
decode at 160x90 — ~1s per 10s take) catches the slow/static take at
fire time, when a re-fire is cheap, instead of at the user's playback
verdict when it is not. The concrete next step: add an M6 column to the
volley QC (threshold to calibrate on the MV-14 takes already ledgered:
compute M6 for all 46 KEEP takes + the rejected ones and set the bar
where the two populations separate), then gate takes on it alongside
the existing motion audit. Everything else in this sprint is supporting
evidence; that is the change that stops another v2.

# SPRINT 4 — c11_mir: the C11 MIR core (2026-11-11)

Survey pick #1 (SPRINT_2026-11-11_SLERM_SURVEY.md §8): extend the
sprint-3 C11 beat tracker into the MIR core — every audio feature
the pipeline takes from librosa/Essentia, in one dependency-free
binary (libc + libm only), validated against the libraries it
replaces. Code: `detection-research/c11_mir/` (renamed from
`c11_beat/`; `git mv` preserves history). `c11_mir.c`, 879 lines.
Build: `gcc -std=c11 -O2 -Wall -Wextra`, zero warnings. One binary,
two modes (`beats` default, `features`); `beat_tracker` is the same
source built under the old name.

## Step 0 — onset-strength floor (sprint 3's owed follow-up)

`--floor FRAC`: after DP backtracking, drop beats whose local flux
peak (max over ±1 frame) is below FRAC × median(flux). Default 0 =
off (sprint-3 behaviour, exact).

| track | floor 0 | floor 1.0 | dropped (times) |
|---|---|---|---|
| MV-14 | 247 | 237 | 10 |
| MV-13 | 298 | 292 | 6 — 8.27, 21.33, 36.30, 87.46, 92.45, 185.54s |
| MV-12 | 247 | 246 | 1 — 113.97s (outro tail) |

The floor does what it was designed for: it removes lattice beats
in quiet regions (MV-13's 8.27s intro, 185.54s outro tail, MV-12's
113.97s outro tail) — but two of MV-13's drops (87.46s, 92.45s)
sit mid-track in a quieter bridge section, so the floor is a
heuristic, not a proven musical improvement: it removes weak-onset
beats a listener might still tap. Grid agreement is unchanged by
the floor on both tracks (MV-13 median |off| 0.1375 → 0.1390s,
MV-12 0.1100 → 0.1080s), so it is a safe cleanup, not a precision
gain. The default stays OFF; `--floor 1.0` is opt-in. (The
pre-compaction floor-sensitivity study found no clean separation
either: at 1.0× median the floor drops 6/238 mid-track MV-14 beats
plus 4/9 edge beats — a tradeoff, not a filter.)

### Tempo / phase on MV-13 + MV-12 vs measured grids

Both tracks show sprint 3's flat-plateau pattern — the tempo is a
selection inside a plateau, not a peak:

- **MV-13** (measured 97.0 BPM / 0.619s / 0.250s): AC flat 0.5094
  across 95.0–97.0 BPM. The C tool reports 95.0 (first max in the
  60→200 scan); median IBI of the DP beats is 0.624s → 96.15 BPM,
  identical to librosa's 96.15 BPM. Phase at the measured period
  from the C flux: 0.19s vs measured 0.25s.
- **MV-12** (measured 131.5 BPM / 0.456s / 0.250s): AC flat 0.7328
  across 129.0–131.5 BPM. The C tool reports 127.5 — same lag as
  131.5 (at 16 ms hop, one lag frame spans ~4 BPM at 130 BPM, so
  the 0.5-BPM scan cannot resolve inside the plateau; 127.5–131.5
  all map to lag 29 frames = 0.464s period). Median IBI 0.464s →
  129.31 BPM, identical to librosa's 129.31 BPM. Phase at the
  measured period: 0.29s vs measured 0.25s.

DP beats vs measured grid:

| track | DP median \|off\| | DP within 100ms | librosa median \|off\| | librosa within 100ms |
|---|---|---|---|---|
| MV-13 | 0.1375s | 40.6% | 0.1370s | 34.9% |
| MV-12 | 0.1100s | 46.2% | 0.1100s | 46.3% |

**Honest limit: the sprint-3 DP advantage does NOT generalise.**
On MV-14 the DP beat librosa (0.088s vs 0.145s median offset); on
MV-13/MV-12 the two are equivalent (MV-13 within-100ms slightly
favours the DP, 40.6% vs 34.9%; MV-12 is a dead tie). On both
tracks the DP and librosa agree with each other far better than
either agrees with the rigid global grid — the grid's single
global phase is the loose part, same lesson as sprint 3.
Per-word ASR anchors stay the timing authority. Full numbers:
`c11_mir/c11_mir_mv13_mv12.json`.

## Step 1 — features (on the STFT core, 1024/256 Hann, 16 kHz mono)

MFCC (13, mel 128 Slaney, DCT-II ortho); chroma/HPCP (12);
RMS envelope; spectral centroid; rolloff (0.85); spectral
contrast (6 octave bands, quantile 0.02, dB); per-beat band
loudness (Essentia BeatsLoudness shape: spectrum energy per beat
segment, whole + bands [20,150,400,3200,7000,22000] Hz);
per-beat RMS; tempogram (384-lag autocorrelation of the onset
envelope, FFT-based, L-inf normalised per frame).

Two implementation details that mattered, found by validation
(not by reading):

1. **MFCC ref.** librosa.feature.mfcc calls `power_to_db(S)` with
   NO ref argument — the default ref is 1.0 (absolute dB), not
   ref=max. My first build used ref=max; coefficients 1–12 matched
   at corr 1.0 but MFCC[0] was off by a constant 344 (the DCT DC
   term absorbs any constant log offset). Fixed to ref=1.0.
2. **STFT window.** Sprint 3 used the symmetric Hann (scipy's
   convention). With it, spectral contrast end-to-end was corr
   0.998955 — below the bar — because contrast's valley is a
   single-bin minimum in band 0, and null depths are extremely
   sensitive to the window (max|diff| 16.9 dB at isolated frames,
   median |diff| only 0.02–0.03 dB). Switching to the periodic Hann
   (librosa's convention) takes contrast to corr 1.000000,
   max|diff| 5e-5 dB — and the DP beats are bit-identical on MV-14
   and MV-12 under both windows, differing by one frame on one
   beat out of 298 on MV-13 (181.792s → 181.776s). The window
   switch is adopted; sprint 3's symmetric-Hann `flux.txt` stays
   as the historical artifact.

## Step 3 — validation (bar: corr ≥ 0.999 vs librosa on MV-14)

`compare_mir.py` compares two ways per feature: (a) end-to-end —
C features vs librosa 1.0.0 features from librosa's own STFT;
(b) isolated — librosa features computed FROM the C magnitude
spectrogram (dumped with `--dump-mag`), which isolates feature
math from the front end. Band loudness / per-beat RMS are checked
against an independent numpy implementation of the same
definition. Full numbers: `c11_mir/c11_mir_validation.json`.

| feature | end-to-end corr | max\|diff\| | isolated corr |
|---|---|---|---|
| MFCC (13×frames) | 1.000000 | 0.00053 | 1.000000 |
| chroma (12×frames) | 1.000000 | 1.6e-6 | 1.000000 |
| RMS | 1.000000 | 5.2e-7 | — (time-domain) |
| spectral centroid | 1.000000 | 0.005 Hz | 1.000000 |
| spectral rolloff | 1.000000 | 15.63 Hz | 1.000000 |
| spectral contrast | 1.000000 | 5.1e-5 dB | 1.000000 |
| tempogram (384×frames) | 1.000000 | 1.9e-4 | — (C flux in) |
| tempogram mean/lag | 1.000000 | 1.3e-6 | — |
| per-beat loudness (6 bands) | 1.000000 | 5.0e-5 dB | — (numpy reimpl.) |
| per-beat RMS | 1.000000 | 5.9e-7 | — (numpy reimpl.) |
| flux vs scipy | 1.000000 | 5.6e-7 | — |

**ALL PASS — every feature at corr 1.000000 (6 dp).** The
residuals are librosa's float32 rounding (isolated checks agree
to ~5e-7) plus rolloff's one-bin quantisation: its 15.63 Hz
max|diff| is exactly one FFT bin on a single threshold-crossing
frame. The tempogram's 1.9e-4 comes from feeding librosa the
6-decimal flux dump; the mean-per-lag agrees to 1.3e-6.

## Performance

Beats mode ~0.6s, features mode ~2.1s on the 161.6s MV-14 track
(1.5 shared CPUs, 6 GB). Peak memory ~120 MB (mag + power +
tempogram, all float64). No librosa, no Essentia, no torch at
runtime: the only Python left in this corner of the pipeline is
the validation harness.

## What this unlocks / what's next

- The pipeline's librosa calls for tempo/grid, MFCC, chroma,
  centroid, rolloff, contrast and tempogram can now be replaced
  by one binary. Essentia's BeatsLoudness is covered in shape
  (energy per beat segment per band — arithmetic, not learned).
- Remaining librosa users in the pipeline: the lyrics stack
  (Whisper — model-bound, do not SLERM) and the per-project
  assembly scripts' tempo/energy probes (survey §8 debt: those
  scripts are per-project copies and need consolidation).
- Survey #2 (word-time snapper) and #3 (C11 HPSS + RMS-VAD) are
  the next SLERM targets; both build on this core (snapper needs
  the flux + tempogram, HPSS needs the STFT core).
- The floor's mid-track drops (MV-13 87.46s/92.45s) are the one
  open question from Step 0: whether a floor that also trims
  quiet-bridge beats is wanted, or whether the floor should apply
  only to the track edges. Default OFF until that is decided.
